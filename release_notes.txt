RomRaider2 ECU Studio 1.1.0 RC4
================================

RC4 is a development preview of the new RomRaider2 interface. It is ready for
desktop and portable-platform feedback, but the remaining hardware checks are
still required before it can be treated as a stable release.

What changed since RC3
----------------------

Desktop JavaFX cutover

- Made JavaFX the default Editor and Logger shell in the Windows and Linux
  desktop launchers and release workflows. Swing and Compose remain explicit
  compatibility choices during qualification; neither is required by the
  default desktop package.
- Restored the complete desktop command surface around the new shell: Open
  ROM, Save As, Definitions Manager, comparison, user levels, settings, Logger
  definition loading, output-folder browsing, and reversible channel access.
- Added calibration tabs, definition-formatted values and axes, engineering
  units, selected-cell coordinates, a restrained heatmap, direct edits,
  definition increments, undo/redo, restore, and a freely rotatable 3D view.
  Calibration tables can be resized from 60% through 160% using visible
  controls, keyboard shortcuts, or Ctrl+mouse-wheel without changing values.
  Row-axis labels remain visible during horizontal scrolling and aligned at
  the bottom of the table; compact cell text remains readable.
- Added one shared Light/Dark theme state across every open Editor, Logger,
  dialog, detached gauge, chart, and calibration surface. High Contrast is no
  longer exposed by the JavaFX desktop. Explicit JavaFX text colors prevent
  Windows system palettes from reducing light-theme contrast, and Windows uses
  capture-safe text smoothing for remote-desktop and VM sessions.
- Improved native chooser behavior on Linux: loaded definitions stay visible,
  successful checksum updates no longer interrupt Save As, CSV analysis starts
  in the configured log folder, and duplicate ROM extensions are normalized.
- Replaced the legacy recursive calibration-increment retry with a bounded
  conversion loop, preventing malformed or unusually scaled definitions from
  overflowing the desktop UI thread.

Logger

- Rebuilt the main Logger workspace around six views: Overview, Data, Graph,
  Dashboard, Dyno, and Log Analysis. They use the same connection,
  selected-channel list, recording state, and live data.
- Added a faster channel browser with search, grouped counts, current values,
  colour-coded parameter names, touch scrolling, and a visible scrollbar.
- Added Analog, Digital, Trend, and Alarm gauge roles with stable scales,
  consistent number formatting, Standard/Large/Custom sizing, per-gauge color,
  and detachable desktop windows.
- Added per-channel gauge settings. Custom scales and low or high warnings are
  optional, saved between sessions, and use hysteresis to prevent flicker near
  a limit. RomRaider2 never guesses a safety limit for the user.
- Added saved dashboard layouts. Each selected channel can be moved, resized,
  and shown as a Gauge, large Value, live Trend, or warning-focused Alarm tile.
- Added clearer connection and recording controls, live session totals,
  responsive narrow layouts, and Ctrl+1 through Ctrl+5 view shortcuts.
- Kept the established MAF, Injector, Dyno, and saved-log tools available while
  removing duplicate live-data workspaces.
- Moved Logger-definition installation and validation off the interface thread.
  Large definitions now show progress and roll back cleanly if validation
  fails.
- Added an explicit Reconnecting state with a capped 1/2/4/5-second retry
  schedule and clearer disconnected feedback.

Editor and live tuning

- Refreshed the Editor toolbar, calibration browser, search field, inspector,
  empty workspace, buttons, tabs, and scrollbars so the desktop interface uses
  one visual system on Linux and Windows.
- Replaced the dense legacy startup notes box with a larger themed RC4 welcome
  surface that is easier to scan and scroll.
- Moved the unsaved-ROM confirmation into the same integrated desktop dialog
  style used by startup and definition setup.
- Updated definition-match and Logger configuration warnings to use the shared
  desktop dialog style on Linux and Windows.
- Removed the bright legacy split-pane dividers that remained in dark and
  SteamOS layouts.
- Reworked the active calibration surface with a framed heatmap, a clearer
  teal selection outline, labelled actions when space allows, and a cell-edit
  strip that wraps instead of hiding controls on narrow windows.
- Added an opt-in replacement calibration grid backed by the current ROM
  table. It shows real axes, values, changed cells, selection details, and
  both-axis scrolling. Single-cell edits now use the same scaling, range
  checks, ROM bytes, definition fine/coarse increments, and undo/redo history
  as the classic grid. Arrow keys move the active cell, and Enter applies typed
  input. A changed cell can be restored to its loaded value without resetting
  the rest of the table.
- Added active-cell Ctrl+C/Ctrl+V and Ctrl+Z/Ctrl+Y shortcuts to the new grid.
  Pasted values still pass the table's normal validation and ROM history.
- Added Shift+arrow and Shift+click range selection plus tab/newline block copy
  and paste to the replacement grid. A pasted block is validated before any
  cell changes and becomes one undoable operation. Ctrl+A selects the full map.
- Added larger touch targets and kept scaling useful from small laptops through
  high-DPI and garage displays.
- Added loaded-ROM recognition for DimeMod, CarBerry, and MerpMod. Recognition
  uses explicit ROM identity or branded definition tables and stays separate
  from live ECU verification.
- Added mapped-feature details for CarBerry and MerpMod instead of limiting the
  ROM-modification view to DimeMod features.
- Added quick counts and clearer status colours to the ROM-modification view so
  mapped definition content and live ECU evidence are easier to tell apart.
- Standardized table spacing, headers, and alternating rows across Logger
  channels, live values, offline analysis, Editor live data and changes, ROM
  comparison, modification details, and the live-tune preview.
- Added a restrained teal treatment to live parameter and analysis channel
  names so values scan faster without colouring every table cell.
- Removed the default Subaru/Engine ECU label from an empty Editor. Vehicle and
  ROM-modification context now stays hidden until a ROM or real session gives
  the application evidence to show it.
- Added a read-only Tune inspector that can review one table or every changed
  table, including byte ranges, before/after values, and the checks that still
  block live execution.
- Added a clear Ready to Review or Offline Preview badge to the Tune inspector
  without adding any connection or write action.
- Added bounded live-tuning plans with overlap detection, stale-value checks,
  exact ECU identity matching, and readback verification.
- Retained the DimeMod RAM Tune signature address and lookup-table size from
  the current ECU session so later address qualification does not rely on the
  feature bit alone.
- Added a separate preflight failure when RAM Tune is advertised without valid
  runtime signature and lookup-table metadata.
- Covered 3D row gaps and X/Y axis edits when building an offline plan from
  changed Editor tables.
- Kept live ECU memory writing restricted to the mock transport. Production RAM
  writing and flashing are not available.

Android and SteamOS

- Added a native Android gauge dashboard shared by simulated and read-only live
  samples. It has five styles, fixed scales, min/current/max values, saved theme
  selection, peak reset, and an offline visual demo that does not need an ECU.
- Kept Android ROM editing definition-backed and read-only toward the vehicle.
  Saved ROM copies still require checksum and desktop review and must not be
  flashed from the preview.
- Kept the Android Subaru SSM K-Line path foreground-only and read-only. It can
  identify an ECU, resolve a profile, display converted values, and record CSV,
  but connected qualification remains scheduled for RC5.
- Added a SteamOS handheld profile with one dark Steam-like theme, larger touch
  controls, a 1280x800 maximized layout, and a supported Non-Steam Game setup
  guide. The bundle does not change the read-only SteamOS system partition.
- The existing macOS previews are unchanged in this visual pass. Mac work is
  paused until the Linux, Windows, Android, and SteamOS interfaces settle.

Checks completed
----------------

- The shared Java 21 suite and JavaFX desktop tests pass.
- The Android APK and shared portable core build successfully.
- The Linux Java 21 image passes its package checks with the correct platform
  JavaFX modules, no Compose/Skia artifacts, and no ROMs, definitions, or
  private vehicle files. The separate SteamOS bundle also passes its package
  checks.
- Logger views, gauge styles, warning states, first-run definition prompt, and
  the refreshed Editor shell have passed isolated Linux rendering checks.
- The Windows launcher and release workflow now select JavaFX, and the shared
  source passes the Java and JavaFX suites. A fresh native Windows JavaFX image
  still needs its normal/high-DPI visual qualification before release.

Known limits
------------

- RC4 remains a development preview.
- No new in-car qualification is planned until RC5.
- Android background logging, reconnect handling, and connected SSM testing are
  not complete.
- Mitsubishi Lancer Evolution MUT-II still needs vehicle qualification.
- ECU flashing and production ECU memory writing are not available.
